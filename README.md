# Подготовка карт для тактического симулятора Civ V

Генерация Пангеи, сохранение ландшафта, отбор участков 16×16 и локальный просмотрщик. Добавлено отдельное нативное ядро боя CP Only для воинов, лучников, лучников на колесницах, копейщиков и всадников: [правила, Python API и сценарии](docs/combat.md).

Сборка боя: `.venv\Scripts\python.exe tools\build_combat.py`. Пример: `.venv\Scripts\python.exe -m civ5sim run scenarios\duel.json --commands scenarios\duel_commands.json --out build\duel-final.json --replay build\duel-replay.json`. Поддерживаются оба режима видимости и оба варианта урона; опыт и приобретаемые повышения отсутствуют.

Полный матч двух Python-агентов: `.venv\Scripts\python.exe -m civ5sim match scenarios\match-example.json --out build\match-example`. Организатор расставляет армии на сохранённой карте, останавливает бой при уничтожении армии или по лимиту раундов и сохраняет результат, финальное состояние и реплей. Составы и лимит обязательны в конфигурации. [Настройка матчей и подключение агентов](docs/combat.md#организатор-матча).

Готовый результат: [просмотрщик десяти участков](artifacts/pangaea-42/viewer.html). Открывается обычным браузером, без сервера и интернета. В списке есть исходная карта и каждый участок; доступны координаты, кандидаты стартовых клеток, сведения о клетке и выгрузка JSON.

## Запуск

Из `E:\civ5_sim`, PowerShell:

```powershell
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe tools\build_native.py
.venv\Scripts\python.exe -m civ5map generate --seed 42 --count 10
Start-Process artifacts\pangaea-42\viewer.html
```

Первая сборка требует Visual Studio с C++ x64 Build Tools. `build_native.py` находит её через `vswhere`; сборка происходит только внутри `build/`. Исходники игры и SDK не изменяются. Для генерации достаточно Python, Lupa, собранной `build/fractal.dll` и файлов установленной игры. Исполняемый файл Civ V не запускается.

Пути по умолчанию:

- игра: `E:\civ5\Sid Meier's Civilization V` (переопределяется `generate --game ...`);
- SDK: `E:\civ5\CvGameCoreDLL_Expansion2` (переопределяется `build_native.py --sdk ...`).

Другой набор:

```powershell
.venv\Scripts\python.exe -m civ5map generate --seed 43 --out artifacts\pangaea-43
```

`--world-size` — 0…5 (дуэль…огромная; по умолчанию 3, стандартная 80×52). `--age`, `--temperature`, `--rainfall`, `--sea-level` соответствуют оригинальным опциям: 1…3, 4 — случайная, по умолчанию 2. Для маленького мира может не найтись десяти подходящих участков: укажите меньший `--count` или другой seed. Отбор в этом случае завершается явной ошибкой, без подстановки непригодных карт.

Произвольная вырезка и просмотр сохранённых карт:

```powershell
.venv\Scripts\python.exe -m civ5map crop artifacts\pangaea-42\world.json --x 20 --y 15 --out artifacts\manual.json
.venv\Scripts\python.exe -m civ5map view artifacts\manual.json --out artifacts\manual-view.html
```

## Что перенесено

Оригинальные `Pangaea.lua`, `FractalWorld.lua`, `TerrainGenerator.lua`, `FeatureGenerator.lua`, `MapGenerator.lua`, `MapmakerUtilities.lua` читаются из установленной игры. При наличии Lua-файла дополнения приоритет: BNW → G&K → базовая игра. Выполняются стадии `GeneratePlotTypes`, `GenerateTerrain`, `AddRivers`, `AddLakes`, `AddFeatures` с пересчётом областей.

`CvFractal.cpp/.h` собираются из SDK отдельно. Алгоритмы фрактала и горных хребтов не переписаны: заменены инфраструктурные include и контейнер `FStaticVector` на `std::vector`, добавлены C-обёртки. Геометрические функции извлекаются из SDK. Генератор случайных чисел воспроизводит 32-битную последовательность `CvRandom`; он общий для Lua и C++.

Python реализует используемую часть API `Map`, `Plot`, `Area`, справочники XML и правила допустимости особенностей местности. Это профиль **обычной BNW**, а не Community Patch / Vox Populi. Исходники Community Patch просмотрены, но они не подменяют стандартный генератор.

Ограничения:

- Используется Lua 5.4 через Lupa с совместимостью `table.maxn`, `unpack`, `table.fill`, `math.clamp`. Поэтому не обещается побитовое совпадение карты с Civ V по одному seed. Воспроизводимость проверяется внутри этой реализации при одинаковых исходниках и зависимостях.
- Оригинальные Lua-скрипты не исправляются, включая особенности их индексации; преобразование `nil` в целый ноль у `SetPlotType` сохранено по поведению SDK-привязки.
- Нет стадий размещения цивилизаций, нормализации стартов, ресурсов, чудес, руин и оформления континентов. Итог — природный ландшафт **до нормализации стартовых позиций**.
- Реализована только часть движкового API, нужная выбранному конвейеру. Полная эквивалентность игровому движку не доказана сравнением с экспортом игры.
- Не загружаются моды и произвольные SQL-изменения игровой базы. Файлы игры/SDK требуются локально; их копии не включены в исходники проекта.

## Формат и вырезка

JSON `schema: 1`: `width`, `height`, `row_parity`, `wrap_x`, `tiles`, `metadata`. Массив клеток идёт по строкам: `index = y * width + x`, Y растёт на север. Отдельные поля клетки: `terrain`, `elevation`, `feature`, `rivers`.

Реки хранятся на трёх принадлежащих клетке рёбрах **E, SE, SW**. Значение `-1` — реки нет; 0…5 — исходное направление течения Civ V (N, NE, SE, S, SW, NW). Реки остальных рёбер принадлежат соседям. У вырезки дополнительные `boundary_rivers` сохраняют реки, владельцы которых остались снаружи.

`row_parity` сохраняет сдвиг нечётных рядов исходной карты: при вырезке с нечётного Y нельзя просто обнулить чётность. Вырезки имеют закрытые границы; переход через шов исходного мира сейчас не поддерживается. `metadata` сохраняет seed, параметры, SHA-256 использованных исходников, сведения о сборке и координаты вырезки с хешем родителя. Сам JSON — окончательный воспроизводимый артефакт даже при последующем обновлении генератора.

Автоматический отбор требует связную область минимум на 65% поля и минимум по 10 проходимых клеток в левой и правой полосах шириной 3 клетки, принадлежащих **одной** области. Вода и горы для отбора непроходимы; реки не разделяют область. `spawn_candidates` — возможные позиции, не расстановка армий и не балансировка сценария. Соседние выбранные окна разнесены по происхождению, но могут перекрываться.

Для обучения и проверки следует разделять набор **по исходным мирам/seed**, а не случайно делить соседние вырезки одного мира.

## Проверки

```powershell
.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тесты проверяют 32-битный RNG, повторяемость генерации, изменение seed и параметров, слои местности, реки, соседство и чётность вырезок, сохранение граничных рек, связность стартовых зон и JSON round-trip. Интеграционные тесты явно пропускаются без локальной игры или собранной библиотеки.

Дополнительные инструменты разработки:

```powershell
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe -m ruff check civ5map tools tests
.venv\Scripts\python.exe tools\check_viewer.py artifacts\pangaea-42\viewer.html
```

Последняя команда использует установленный Edge в headless-режиме, проверяет переключение карт, координаты, стартовые зоны, сведения о клетке и скачивание JSON; сохраняет `preview.png`.
