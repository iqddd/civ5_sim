# Диагностика решений

Инструмент работает с любым реплеем текущего физического формата и с отдельно
сохранёнными запросами. Номера команд соответствуют веб-панели, начиная с 1.
Ни исходный реплей, ни поведение агента при диагностике не меняются.

## Запись

```powershell
python -m civ5sim match config.json --out build/example --diagnostics compact
python tools/resume_combat_replay.py replay.json build/continuation --after 20 --search-config config-search.json --diagnostics full
```

`off` (по умолчанию) не пишет пакет. `compact` сохраняет точные запросы,
настройки, результаты, наблюдения и происхождение назначений.
`full` дополнительно записывает значения из выполняемых нативных вычислений.
Программный интерфейс: `run_match(..., diagnostics="compact")`; пакет сохраняет
`MatchOutcome.save()`. Продолжение записывает только новые вызовы, без выдуманной
диагностики сохранённого префикса.

Файл `diagnostics.json.gz` имеет собственную схему 1. Подробные трассы лежат
в `diagnostic-traces/`, проверяются по SHA-256 и загружаются по запросу. Во время
матча они сжимаются во временные файлы, а не накапливаются деревьями в памяти. Он связан с семантическим
SHA-256 реплея, содержит хеши библиотек, исходников и подготовленных правил,
Git HEAD, дедуплицированные состояния, вызовы и запросы. В запросе отдельно
от наблюдения хранится привилегированный вход поиска. Эти данные не становятся
доступны обычному агенту. Диагностика использует replay schema 2 и текущий ABI 8.

Вызовы, задачи и запросы имеют идентификаторы. Действие ссылается на конкретный
объект назначения исходного ответа: очередь и использование кэшированного
плана не превращаются в новый поиск. Действия без назначения показываются
как непосредственные правила агента; детали сторонних агентов пакет не выдумывает.

## Разбор

```powershell
python tools/diagnose_combat.py build/example/replay.json --commands 5 8 --output build/explanation
python tools/diagnose_combat.py build/example/replay.json --commands 8 --repeat --output build/repeated
python tools/diagnose_combat.py build/example/diagnostics.json.gz --query 0 --repeat --output build/query
```

Выход: `report.md` и `report.json`. Отчёт связывает команду с исходным запросом,
показывает полный план и границу RESTART, оценки и счётчики. Полная трасса
остаётся в JSON; Markdown содержит выбранную ветвь и RECOVERY.

`--repeat` — **эксперимент текущим кодом**, а не историческое свидетельство.
Сравниваются полные ответы, включая назначения, оценки, причины и счётчики.
Одинаковый ответ сам по себе не доказывает одинаковость всех внутренних решений;
хеши среды сохраняются отдельно. Запрос можно повторить без исходного матча.

Старый реплей без пакета даёт проверенное состояние и прежние `ai_events`,
но не позволяет достоверно восстановить незаписанный запрос и память координатора.
Несовместимый физический движок или нарушение хеша прерывают реконструкцию.

## Альтернатива

```powershell
python tools/diagnose_combat.py replay.json --commands 8 --alternative actions.json --reply greedy --output build/alternative
```

`actions.json` — массив обычных команд симулятора с `kind`, `unit`, `target`.
Последовательность исполняется перед указанной командой, на отдельном состоянии
с исходным RNG. Проверяется законность каждого действия. При `--reply greedy`
история greedy восстанавливается и сверяется с префиксом; после альтернативы
завершается свой ход и исполняется один полный ответ противника. Требуется
соответствующий `result.json`. Автоматический ответ других агентов не поддерживается.
Такой опыт не доказывает оптимальность или безопасность последующих ходов.

## Значение трассы

| Семейство событий | Источник и смысл |
|---|---|
| `recruit_*` | CP `FindUnitsWithinStrikingDistance`; допуск до ограничения состава |
| `root_*`, `drop_wounded_mover` | CP `addAvailableUnit`, `dropSuperfluousUnits`; корневой отсев |
| `consider_destination`, `destination_area_rejected`, `continuation_rejected`, `preferred*`, `shot_before_limit` | CP `getPreferredAssignmentsForUnit`; область, движение, рейтинг и лимит предпочтений |
| `attack_*`, `move_score` | CP `ScoreAttackDamage`, `ScorePlotForCombatUnitMove`; прогноз и составляющие оценки |
| `danger_*` | Тактическая модель CP: корневой индекс угроз, исключения, туман, поправки видимости/самоубийства; `cached` использует ранее вычисленное значение |
| `turn_end` | CP `ScoreCombatUnitTurnEnd`; HP, опасность до/после поправок, союзники, порог и допустимость |
| `end_skip_*`, `final_evaluation` | CP `addFinishMovesIfAcceptable`, `isKillOrImprovedPosition`; пропущенные проверки, риск и улучшение |
| `combo`, `child`, `expand`, `completion`, `search_result` | Комбинации CP и управление поиском переноса; идентификаторы не зависят от повторного использования памяти |
| `physical_rejection`, `equivalent_rejection`, `superseded`, `branch_limit` | Исполнение и собственная таблица эквивалентности/ограничения поиска |
| `physical_danger_*` | Подробная модель ответа противника в адаптере симулятора, используемая поддержкой; это не тактическая модель CP |
| `recovery_*` | Адаптация `PerformOpportunityAttack`, `FindSafestPlotInReach`, `ExecuteMovesToSafestPlot` без Homeland AI |
| `support_*`, `approach_rejected` | Нейтральная адаптация лечения и сближения |

Точное сопоставление исходникам CP: [combat-ai-cp-transfer.md](combat-ai-cp-transfer.md).
Событие отказа фиксирует встретившуюся проверку, а не доказательство отсутствия
какого-либо другого допустимого плана. Свойства потенциального убийства и
бюджет риска сохраняют действующую семантику.

Нативная трасса ограничена 64 МиБ **на запрос**. При превышении `truncated=true`,
поиск продолжается без записи, итог ответа хранится отдельно. Сжатый пакет
целого матча может быть большим; для обычного расследования предпочтителен
`compact` с подробным повтором нескольких запросов. Сбор не выполняет
дополнительных оценок или действий движка; ошибки записи отмечают неполный пакет.
Диагностическое время нельзя выдавать за производительность обычного поиска.

Добавлены только дополнительные функции C ABI `cai_trace_enable`, `cai_trace_data`,
`cai_trace_status`. Буфер принадлежит контексту, живёт до следующего нативного
вызова и не разделяется между планировщиками. Старые структуры не расширены.

## Замер накладных расходов

```powershell
python tools/benchmark_decision_diagnostics.py build/example/diagnostics.json.gz --output build/diagnostic-benchmark.json
```

По умолчанию: первые 24 запроса, пять повторов в каждом режиме. Проверяется
совпадение полных результатов, сохраняются время и размер сжатых данных.
Это изолированный замер запросов с новым контекстом на каждый запрос, не время
матча. Однократное хеширование исходников и сохранение итогового пакета вынесены за
замер; сжатие временных трасс в режиме full входит во время запроса.
