# Инварианты локального поиска, 0.7.2

2 ноября 2026. Проверка замечаний к `planner.cpp`; публичный C ABI остаётся 5,
сборка остаётся C++17, паспорт физических правил не меняется.

## Исправленное поведение

- Раннее окончание проверяет уничтожение каждого исходного врага по ID.
  Новый убитый враг не заменяет исходную цель; лишние убийства не мешают
  завершению после уничтожения исходного набора. Пустой исходный набор сам
  по себе не завершает поиск. При исчерпании действий всех участников поиск
  заканчивается независимо от оставшихся целей.
- Это явное исправление условия `CvTacticalPosition::isEarlyFinish`
  (`CvTacticalAI.cpp:8733`), где сравниваются только количества. Область
  исходной задачи не расширяется новыми врагами: после уничтожения исходных
  целей следующие задачи остаются координатору.
- `RESTART` содержит ID первого участника, действительно обнаружившего
  врага в исполняемой паре. Запись добавляется после обеих частей. Для
  обмена проверяется, какой из двух новых источников обзора видит контакт.
  Это исправление атрибуции: закреплённый CP использует первый ID пары.
- `FINISH_TEMP` и `BLOCKED` получают тайл и движение из текущего ребёнка.
  Нынешний сборщик исключает устаревание этих полей, но исполнитель больше
  не зависит от знания об ограничениях сборщика.

## Типы и фазы

`UnitId` адресует полный физический реестр; `SlotIdx` — слот выбранной
группы. Между ними и целыми числами нет неявного преобразования.
`SelectedUnits` проверяет соответствие; `UnitValues<T>` и `SlotValues<T>`
принимают только свой тип индекса. Внутри тактических оценок слот также
передаётся как `SlotIdx`.

`SlotState::{Pending,Finished,Blocked}` и
`MoveFlag::{None,Moved,Swapped}` заменяют два разных соглашения о 0/1/2.
BLOCKED не превращается в физическое ожидание. Для формата ключа значения
явно преобразуются в числа; публичные структуры ABI не изменяются.

`stationary_assignment` именованно заполняет все поля записи из состояния
юнита. При физическом переходе изменяемые поля задаются по именам рядом с
результатом команды. Позиционных инициализаторов `CaiAssignment` в
планировщике больше нет; переход на C++20 не требуется.

`CandidateExecutor` применяет пару только к временной ветке. ID проверяются
до индексирования; неправильная структура обмена и несоответствие обратной
записи приводят к `logic_error` также в release-сборке. Обратной записи
нельзя присвоить оценку через непроверенный `assignments.back()`.

`evaluate_final_position(const TacticalPosition&)` возвращает оценку и
предлагаемые FINISH без изменения позиции; изменяться могут только кэши
запросов контекста. `finalize_assignments` устанавливает их после принятия,
отказывается устанавливать отклонённый результат и защищает от повторного
завершения того же юнита. Ветка с отрицательной оценкой не остаётся с
частично переписанной историей.

Бонус `kUntouchedEarlyFinishBonus = 123` имеет ссылку на
`addFinishMovesIfAcceptable` исходного CP. Он сохраняет исходную оценку за
нетронутый юнит, доступный последующей задаче.

## Очередь и счётчики

Проверка терминального корня вынесена перед очередью; в очередь попадают
только нетерминальные дети. Достижение `max_completed` одинаково обрабатывает
корень и детей: это исчерпание бюджета, которое может возвращать пригодный
найденный план. `peak_positions` явно вычисляется по числу удерживаемых
слотов. В текущем растущем пуле оно закономерно совпадает с `generated`.

`key()` по-прежнему копирует состояние видимости и тактические клетки.
Замена представления ключа и кэширование — отдельная оптимизация, в это
исправление не включены.

## Проверки

Добавлены нативные группы `planner_invariants`, `planner_finalization`,
`planner_combo_contacts`: исходный/новый ID, отрицательный и невыбранный ID,
обратная запись без свопа, свежая клетка служебного назначения, отказ без
переписывания записей, отдельная установка FINISH, повторная финализация,
реальное обнаружение вторым движением пары и оценки двух частей обмена.

На 49 сохранённых входах сравниваются полные результаты с версией 0.7.1:
назначения, оценки, причина и все счётчики. Непустые планы на входах со
snapshot обеих версий исполняются ядром. Новые ошибки воспроизводятся
отдельными направленными сценариями; сохранённый корпус сам по себе их не
покрывал. Результат проверки:
`artifacts/combat-ai/planner-invariants-20261102.json`.
