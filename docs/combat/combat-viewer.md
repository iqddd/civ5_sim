# Пошаговый просмотр матчей

Локальный веб-просмотрщик читает сохранённые реплеи. Обычный реплей перед
показом исполняется через боевое ядро со сверкой результатов и SHA-256
каждого состояния. Для архивного schema 2 с прежним паспортом правил
поддерживается `viewer-cache.json.gz`: проверяются SHA-256 точных файлов
replay/result и число кадров, без повторного исполнения нынешним ядром.
Панель явно отмечает прежние правила; просмотр кеша не является проверкой
совместимости старого боя с новым ядром. Для обычного пути нужна собранная
библиотека боя; AI-библиотека для просмотра не нужна.

Из корня проекта:

```powershell
.venv\Scripts\python.exe tools\view_combat.py build\combat-ai-v1-final --port 8766
```

Открыть [просмотрщик](http://127.0.0.1:8766). Аргументом может быть каталог
одного матча, каталог с множеством матчей или отдельный `replay.json`.
Сервер принимает подключения только с этого компьютера.
Кнопка «Закрыть панель» останавливает backend: он завершает активные запросы,
выгружает модели и освобождает порт. Вкладка остаётся со статусом закрытия;
простое закрытие вкладки браузера сервер не останавливает.

Принимаются реплеи schema 2 со снимками schema 2 и историей урона.
Укажите существующий каталог матча, серии или replay; пример пути выше
сам по себе не гарантирует наличие сохранённых боёв. Реплеи schema 1
без истории намеренно не мигрируются и не загружаются.

- Кнопки ‹ / › и клавиши ← / → переходят на одну команду.
- Ползунок позволяет сразу выбрать любую позицию. Шаг 0 — расстановка;
  шаг N — состояние после N-й команды.
- ▶ / Пробел запускают и приостанавливают проигрывание. Скорость выбирается
  рядом с кнопками; Home / End переходят в начало и конец.
- « / » и список ходов позволяют переходить к границам ходов сторон.
- Нажатие на юнита показывает HP, оставшееся движение и состояния на текущем
  шаге. Нажатие на клетку показывает её координаты и ландшафт.
- Колесо мыши меняет масштаб, перетаскивание сдвигает карту; «Вместить»
  возвращает исходный масштаб.
- Режимы обзора A/B используют фактическую видимость выбранной стороны.
  Ландшафт известен целиком: вне обзора сохраняются читаемые холмы, особенности
  и реки; клетки вне обзора заметно затемнены, значки рельефа остаются тёмными
  и не выцветают вместе с клеткой. Горы имеют отдельную нейтральную окраску
  и подпись «Горы» без базового типа местности. Вражеские юниты скрываются.
  Это просмотр полного реплея: журнал команд и суммарные показатели армий
  содержат полную информацию о бое.
- Пункт журнала открывает состояние после выбранной команды. Справа также
  отображаются диагностические события CP на этой границе команд.

Стрелка соединяет исходную и конечную клетки последнего действия;
она не изображает промежуточный маршрут. При прерванном движении исходная
цель команды отмечается пунктиром. W / A / C / S / H обозначают воина,
лучника, лучника на колеснице, копейщика и всадника. Полоска — HP;
золотая точка означает использованную атаку.

Библиотека обновляется каждые 30 секунд и кнопкой ↻. Для каталогов матчей
она показывает записи с сохранённым `result.json`; одинаковые повторы
`0`/`1` серии объединены. Одиночный реплей можно открыть без результата.
Некорректный реплей выводит ошибку; он не выдаётся за проверенный.
Просмотрщик сохраняет в памяти до трёх восстановленных реплеев.

Для произвольной серии `summary.json` может содержать строку `viewer_summary`
и `summary.matches`. Панель показывает эту сводку дословно через `textContent`;
такие серии не получают специальную сводку приёмки CP–greedy.

Ветка с заменой команды (`experiment.kind = counterfactual_action`) открывается
на `prefix_commands`, перед заменённым действием. Её описание показывает замену
и модель продолжения; финал отображается как исход полного матча. Статистика
поиска и надпись о конце найденного плана относятся только к реплеям с `base_stats`.

## Ручные действия и вариации

Остановите реплей **перед** заменяемой командой и нажмите «Ручной режим».
ЛКМ выделяет юнита; ПКМ по клетке сразу перемещает его, по врагу — атакует
(ближняя/дальняя атака по возможностям юнита), по своему — обменивает местами,
если обмен легален. Пробел даёт выбранному юниту ожидание, не запускает реплей.
Карта сразу показывает результат ядра, урон и остаток движения; выделение
сохраняется для следующей команды. Недопустимый приказ ничего не меняет.
Кнопки: ↶ отменяет команду, «Конец хода», «Создать вариацию», «Отмена».
Список заданных команд свёрнут; выбор модели скрыт, если доступна только одна.
До создания вариации исходный реплей не меняется.
Ручной режим доступен на ходе модели в policy–CP сериях с `case.json`.

«Создать вариацию» сохраняет отдельный матч и открывает его в этой
же панели. Checkpoint берётся из паспорта серии/ветки либо выбирается из
подключённых viewer-policies. Для этой операции checkpoint загружается в отдельном
процессе CUDA FP32 и освобождается при завершении; preview обходится без модели.
Прежний префикс, модельная память, координатор CP и RNG восстанавливаются
helper-командой `ctl_rl.py branch-replay`; новый replay проверяется полностью.
Начатое продолжение завершается перед закрытием backend. Длительность ограничена
10 минутами; ошибка показывается в панели, очередь ручных команд сохраняется.
Новая вкладка не открывается; учебные файлы и checkpoint не изменяются.

## Вероятности действий

Под шкалой времени есть режим «Вероятности действий»: включение расчёта,
выбор одной модели или сравнения всех, температура и фильтр по выбранному юниту.
Показаны все легальные действия, ★ отмечает argmax, ✓ — следующую записанную
команду. Ползунок N показывает состояние **после** команды N; для оценки
команды 142 нужно выбрать 141. Во время проигрывания расчёт ждёт паузы.
Вероятности при температуре T не означают, что в исходном argmax-бою был sampling.

Прямая ссылка может задать позицию `?frame=220`, включить вероятности
`&probabilities=1` и выбрать обзор `&vision=1` (сторона B; также `0` или `all`).
Путь реплея остаётся в `#`, например
`/?frame=220&probabilities=1&vision=1#02-case060-parent%2Freplay.json`.

Подключение моделей — файл `viewer-policies.json` в корне открытой серии:

```json
{"models": [{"id": "parent", "label": "Родитель", "side": 1,
  "checkpoint": "artifacts/rl/RUN/checkpoints/initial.pt"}]}
```

Пути checkpoints отсчитываются от корня проекта; можно указать абсолютный путь.
Другой файл задаётся флагом `--policies FILE` при запуске панели. Модели загружаются
лениво при первом запросе, используется CUDA FP32 при доступной CUDA, иначе CPU FP32;
фактическое устройство показано в панели. AMP/TF32 выключены. Для каждой модели
с нуля восстанавливается вся публичная история выбранной стороны, включая forced
и вручную заменённые команды, с проверкой физического префикса и RNG по хешам.
На ходе другой стороны и в конце боя распределение не рассчитывается.
Результаты кешируются в памяти процесса; обучение и CP не вызываются.
Для модели C2P публичные attack previews вычисляются при восстановлении каждого
её решения и сопоставляются с тем же упорядоченным списком легальных команд.

Проверки:

```powershell
.venv\Scripts\python.exe -m unittest discover -s tests -p test_match_viewer.py -v
.venv\Scripts\python.exe tools\check_combat_viewer.py http://127.0.0.1:8766
```

Браузерная проверка использует установленный Edge и Playwright, проверяет
навигацию, проигрывание/паузу, выбор юнитов, масштаб, обзор, поиск и мобильную
компоновку. Снимки сохраняются в `build/combat-viewer-preview*.png`.
