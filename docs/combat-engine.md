# Боевое ядро и реплеи

Сверено с кодом 8 ноября 2026 года. `civ5sim` — автономный бой двух армий:
C++17 исполняет физические правила, Python загружает сценарии, организует
матчи и сохраняет результаты. C ABI ядра — **2**. GPU и библиотеки обучения
для боя и просмотра не нужны. Полный справочник механик и Python API:
[combat/combat.md](combat/combat.md).

## Сборка и первый матч

Команды выполняются из корня репозитория; на Linux используется Python
соответствующего окружения вместо `.venv/Scripts/python.exe`.

```powershell
.venv/Scripts/python.exe tools/build_combat.py
.venv/Scripts/python.exe -m civ5sim run scenarios/duel.json --commands scenarios/duel_commands.json --out build/duel-final.json --replay build/duel-replay.json
.venv/Scripts/python.exe -m civ5sim replay build/duel-replay.json
```

Сборка извлекает правила из локальных Civ V/CP, подготавливает их в `build/`
и собирает `combat.dll` / `libcombat.so`. Параметры `--game` и `--cp`
задают расположение исходных установок. Для исполнения подготовленного ядра
нужны библиотека и `combat_rules.json`; игра больше не читается.

## Battle и организатор

`Battle` предоставляет команды, наблюдение стороны, снимки и восстановление.
Пять типов: warrior, archer, chariot_archer, spearman, horseman.
Физическая законность, движение, видимость и RNG принадлежат ядру;
AI предлагает команды, а не заменяет их исполнение.

`turn_reset_mode` в сценарии или конфигурации матча: `"legacy"` по умолчанию
сохраняет сброс начинающей ход стороны; `"end_turn"` включает исправленный
сброс заканчивающей ход стороны. Он охватывает укрепление, лечение и
восстановление движения. Снимки/реплеи и планировщик CP сохраняют режим.

```powershell
.venv/Scripts/python.exe -m civ5sim match scenarios/match-example.json --out build/match-example
.venv/Scripts/python.exe -m civ5sim replay build/match-example/replay.json --out build/match-example/verified.json
```

Конфигурация матча задаёт `map`, два непустых состава `armies`, положительный
`max_rounds` и двух `agents`. Сторона 0 начинает; `end_turn` заканчивает
ход стороны, два таких хода составляют раунд. Уничтожение армии проверяется
после каждой команды раньше лимита; лимит даёт ничью. Исключения агента,
недопустимая команда и превышение числа вызовов — технические ошибки.

На бой создаются два независимых агента. `reset(context)` получает публичную
карту без стартовых зон/метаданных, исходные составы и параметры боя.
`act(observation, actions)` выбирает одну допустимую команду; память
сохраняется между вызовами. Обычным агентам не передаются полный снимок,
скрытые потери или RNG. Сервисы планирования CP имеют отдельную границу
доступа, описанную в [Combat AI](combat-ai.md).

`run_match` возвращает `MatchOutcome`; `save(directory)` пишет `result.json`,
`replay.json`, `final.json`. Result schema 1 содержит status/outcome/winner,
reason, параметры, счётчики и hashes. Частично исполненный бой при технической
ошибке также сохраняется. Seed воспроизводимо разделяется между размещением,
боем и агентами; одинаковый общий seed не делает разные политики одной траекторией.

## Форматы и видимость

Карты и сценарии используют schema 1; снимки и `civ5sim.replay` — **schema 2**.
Снимок включает историю урона и обязательное `state.visibility`: две маски
истории обзора. При включённом `CORE_DELAYED_VISIBILITY` новые клетки видны
сразу, покинутые остаются видимыми до границы хода. На границе обе маски
обновляются по текущим источникам. При `fog=false` наблюдение полное,
но история масок всё равно хранится и проверяется.

Реплей содержит начальное состояние и команды с результатами/hashes шагов;
его проверка не требует повторного исполнения AI. Необязательные `ai_events`
описывают решения отдельно от физической последовательности. Старый паспорт
правил нельзя выдавать за совместимый с текущим исполнением по одному номеру
schema: CLI replay сверяет результаты и состояния с текущим ядром.

## Просмотр

```powershell
.venv/Scripts/python.exe tools/view_combat.py build/match-example --port 8766
```

Открыть [локальную панель](http://127.0.0.1:8766). Поддерживаются каталог
матча/серии и отдельный replay; сервер слушает только `127.0.0.1`.
Обычные реплеи проверяются исполнением ядром. Для исторических schema 2
с прежними правилами допускается `viewer-cache.json.gz`: проверяются точные
SHA-256 replay/result и число сохранённых кадров, без переисполнения текущим
ядром. Панель помечает прежние правила; такой просмотр не означает успешный
replay-check новым ядром.

Стрелки переходят по командам, Home/End — к границам, пробел запускает
проигрывание; щелчок показывает юнита или клетку, колесо меняет масштаб.
Режимы обзора сторон используют их маски, однако полный журнал и итоговые
показатели реплея остаются аналитической полной информацией.
Подробности навигации и обновления каталога — в
[справочнике просмотрщика](combat/combat-viewer.md).
