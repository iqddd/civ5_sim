# PPO после имитации CP на целевых армиях

> Исторический протокол / исходная спецификация. Путь сохранён: документ используется конфигурацией или кодом.
> Это условия отдельного этапа, а не актуальный общий справочник; наличие плана не доказывает запуск.
> Проверенные статусы и ограничения: [журнал](experiment-ledger.md); текущее устройство: [справочник](rl-architecture.md).

2026-11-06. Предлагаемое направление одного опыта; обучение этим документом
не запускается. Цель — проверить, превращает ли PPO новую исходную силу BC
в дальнейший прирост побед на целевой смеси. Дальняя цель 75% сохраняется;
для этого опыта важнее положительный прирост относительно BC epoch 10.

## Инициализация и задача

Родитель: `artifacts/rl/cp-imitation-target-scale/checkpoints/epoch-10.pt`.
Загрузить model целиком, включая value head. Не использовать checkpoints
неудачного target PPO. Новый PPO Adam, без моментов BC Adam 1960.
Seed 17, новые training/shuffle namespaces, новые счётчики бюджета.
В новом namespace episode ID можно начать с нуля: это не resume прежнего
случайного потока. Физические повторы считать без фильтрации.

Прежняя целевая смесь: 57 training-worlds, открытые crops 10/12/16,
армии 5–13, все пять типов, симметричные случайные составы с melee/ranged,
баланс категорий, сторон и контакта. Исправленный генератор, HP 100,
fog/random damage, 30 раундов. Обычный CP с прежним SearchConfig.
Ни handicap, ни примесь greedy, ни shaping в этом опыте не вводятся.

## Короткая подготовка critic в начале того же опыта

Замороженная при BC value head больше не откалибрована к изменившемуся
encoder. На первом штатном sampling rollout подготовить только value head:
encoder, GRU и policy head заморожены; targets — полные Monte Carlo returns
1/0/0. Два прохода по реальным позициям, batch 1024, MSE, отдельный временный
Adam LR 1e−4, clipping 0,5. Лимит этой подготовки 120 активных секунд;
начатый batch завершить. Новые эпизоды специально для неё не собирать.

Это ограниченная подгонка на training, не доказательство хорошей калибровки.
Сообщить предсказания, return mean, MSE и EV до/после; EV при нулевой
дисперсии returns обозначить как неопределённую. Политику на фиксированных
входах подготовка изменять не должна. Моменты временного Adam отбросить.

Затем разморозить обычные обучаемые параметры и создать новый PPO Adam.
Для первого rollout пересчитать old_value после подготовки head, сохранить
исходные behavior probabilities и заново вычислить advantages. Начать PPO
на том же rollout: подготовка не потребляет отдельный корпус и не требует
изменения старых действий. Первый PPO Adam counter — 1.

## Основные параметры и бюджет

| Параметр | Значение |
|---|---|
| Модель | Прежняя C/GRU, 1,375 млн параметров |
| Precision | BF16 spatial, FP32 остальное; spatial block 32, padding 256 |
| Reward / gamma / lambda | 1/0/0; 1; 1, полные эпизоды |
| PPO Adam LR | Постоянно 1e−5 |
| Adam | betas 0,9/0,999; eps 1e−5; weight decay 0 |
| Rollout | ≥8192 реальных решений, завершённые волны/эпизоды |
| Epochs / clip / value coefficient | До 4; 0,2; 0,5 |
| Entropy coefficient / grad clipping | 0; 0,5 |
| Adam batch | 1024 реальные позиции, включая forced для value-loss |
| Actor / KL | Только свободные действия; прежняя нормировка advantage |
| GRU | Фрагмент 128, пересчёт prefix текущими весами |
| Приём шага | Полный KL(old || current) по свободным ≤0,015, иначе откат |
| Хранение | CPU rollout и порционная подача, проверенная в target PPO |
| Бюджет | 2 097 152 новых решения или 7200 активных секунд |

1024 позиции PPO — не 1024 свободные BC-метки. Остаток нормировать на
фактический размер; forced не должны создавать policy-gradient.
Параллелизм и microbatch взять из уже измеренного рабочего режима выбранной
машины. Не начинать новую кампанию оптимизации. Выбор локальной/удалённой
машины — отдельное операционное решение; этот документ не арендует машину.

Collection, critic-подготовка, подача, runtime compilation, PPO, KL,
откаты и регулярное сохранение входят в активный бюджет. Боевые оценки
отдельно. Начатую попытку завершить вместе с KL, последнюю волну завершить;
новую попытку после временной границы не начинать.

## Оценки и раннее прекращение

Development — прежние 128 случаев, argmax CP, CPU / 4 workers. Точки:
ноль, 262144, 524288, 1048576, 2097152 новых решений. Ноль — epoch 10,
27/33/68 при том же evaluator; если среда исполнения изменилась, один раз
переоценить родителя. Sampling оценивается по штатным training rollout,
отдельной sampling-кампании нет.

Кандидат — максимум development-побед, tie раньше, родитель участвует.
После первых двух новых оценок, на 524288 решениях: если ни один checkpoint
не превысил исходное число побед, закончить опыт с причиной
`no_development_gain`. Это экономическое правило, а не статистическое
доказательство невозможности позднего улучшения. CE, entropy или снижение
MSE не служат причиной продления. При выбранном checkpoint лучше родителя
продолжить до обычной границы 2 млн / 2 ч.

Дополнительная остановка: пять подряд rollout без единой победы. После
сбора пятого закончить опыт до его PPO-обновления, сохранив собранные данные
и потраченный бюджет. Это сигнал недостатка успешных траекторий, не правило
нулевого градиента для отдельных rollout. Прежняя остановка после трёх
rollout без принятого шага также сохраняется.

При обычной временной остановке оценить последний изменившийся checkpoint
вместо следующей плановой точки. При остановке из-за отсутствия побед
также оценить последнюю изменившуюся модель, если её ещё не оценивали.
При no_development_gain дополнительных оценок не требуется: две нужные
точки уже выполнены. Одинаковые веса повторно не оценивать.

Если кандидат улучшил development — после выбора прежние 256 additional
случаев для родителя и кандидата на одном evaluator. Результат BC 45/71/140
переиспользуется при известной неизменности evaluator/cases; иначе повторить
родителя. Paired CI: 10000 bootstrap, seed 20261103, parent-world. Если
родитель остался выбранным, additional не выполнять. Закрытый test не трогать.

## Что считать результатом

Основное — положительный парный прирост относительно BC epoch 10;
положительная нижняя граница additional CI поддерживает полезность PPO.
25–30% побед на additional — практический ориентир, не обещание.
Показывать карты, категории армий, контакт/разделение и обе стороны.

Training отчёт: доля побед и rollout без побед; raw advantage std;
critic EV/MSE/среднее предсказание; entropy; полный KL и откаты. Не считать
принятые Adam steps свидетельством обучения стратегии. Argmax 17,58% не
приравнивать заранее к частоте побед sampling-политики.

Один компактный run.json, существующие checkpoints/метрики/реплеи. Проверить
правильного родителя и отсутствие изменения policy при подготовке critic,
обновление old_value для первого rollout и штатный behavior replay.
Полный набор тестов и повторные проверки неизменённых компонентов не нужны.
Параметры и данные по ходу не менять, бюджет не продлевать автоматически.
