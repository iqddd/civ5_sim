# Контракт Combat AI: текущее поведение

Актуально на 2 ноября 2026: модуль `0.7.2 CP-07`, C ABI `5`, C++17.
Этот документ задаёт текущее поведение порта. История находится в
[отдельном снимке](combat-ai-contract-history.md); происхождение правил —
в [карте переноса CP](combat-ai-cp-transfer.md), протоколы исправлений —
в [аудите инвариантов](combat-ai-planner-invariants.md).
Полная приёмка CP-07 ещё не завершена. Сравнение решений с прежней версией
проверяет сохранение поведения, но не доказывает оптимальность планов.

## Интерфейсы, владение и сборка

C ABI: `native/combat_ai/combat_ai.h`; Python: `civ5sim.combat_ai`;
внутренние адаптеры правил и ветви: `native/combat_ai/model.h`.

| Объект | Владение и время жизни |
|---|---|
| `CaiBattleState` / `PlanningState` | Снимок карты, полного стабильного ростера, видимости наблюдателя, стороны и хода; без RNG |
| `Branch` | Собственные изменяемые физическое состояние, видимость и память контактов; клоны разделяют неизменяемую карту и геометрию |
| `CaiContext` / `Planner` | Копия конфигурации, рабочая память поиска; один контекст используется последовательно, разные контексты независимы |
| `SearchResult` | Упорядоченные назначения, причина и статистика; Python-значения независимы от контекста |
| `RulesAdapter` / `DangerModel` | Адаптер должен переживать модель; ветви совместимы только со своим адаптером |
| `CallPlanningServices` | Сервис одного вызова агента; после возврата или исключения истекает в `finally` |

Указатели ABI заимствованы только на синхронный вызов. Контекст не удерживает
входные массивы. `Planner.close()` идемпотентен; изменяемых глобальных рабочих
списков нет. Представление `Branch.state()` принадлежит ветви и действительно
до следующего `state()`, изменения ветви или уничтожения.

```powershell
.venv\Scripts\python.exe tools/build_combat.py
.venv\Scripts\python.exe tools/build_combat_ai.py
.venv\Scripts\python.exe tools/check_combat_ai_sources.py --cp E:\civ5\Community-Patch-DLL
.venv\Scripts\python.exe -m unittest discover -s tests
```

Первая сборка подготавливает `build/combat_rules.h` и `build/cp_geometry.inc`.
AI собирается отдельно от боевой DLL и GameCore, используя общие исходники
правил. Выход: `combat_ai.dll` либо `libcombat_ai.so` и native-тесты.
MSVC x64 проверен; наличие Linux-ветки сборки не означает проверку её в этой
среде. При отсутствии подготовленных входов сборка сообщает нужную команду.

## Запросы, результаты и ошибки

`SearchRequest` содержит снимок, сторону, ожидаемый ход, целевую клетку,
упорядоченный список выбранных юнитов, память контактов и необязательную
агрессивность. Цель — ориентир, включая занятую или непроходимую клетку,
а не разрешение на незаконную команду. Порядок выбранных влияет на равенства.

| Поле / ограничение | Значение |
|---|---|
| Карта | До 4096 клеток, каждая ось 1…128; row parity, wrap и fog — 0/1 |
| Ростер | До 512 слотов; ID равен индексу, не переиспользуется после смерти; HP 0 остаётся в ростере |
| Выбранные | 0…13 уникальных живых собственных ID; неизбранные не получают назначений |
| Типы | Пять сухопутных типов ядра; реки — шестибитная маска; движение — шестидесятые очка |
| Состояние | Допустимые типы/поля, проходимые клетки и отсутствие наложений живых; видимость должна совпадать с вычисленной маской наблюдателя |
| Память | Своя сторона, допустимые время и вражеские ID без повторов; исторические мёртвые контакты разрешены |
| Отсутствие | `-1` для отсутствующего ID/клетки; ID 0 и клетка 255 обычные значения |

Пустая память `turn=0, side=-1` разрешена для инициализации. Непустая принадлежит
запрашивающей стороне; её время не позже снимка. Время наблюдения контакта
не позже собственного хода при последнем реальном обновлении памяти.
Дубликаты, чужие или отсутствующие выбранные ID и неверные поля отклоняются.

| Причина результата | Смысл |
|---|---|
| `completed` | Лучший найденный допустимый завершённый план |
| `no_plan` | Подходящего плана нет, в том числе для пустой группы |
| `budget_exhausted` | Бюджет исчерпан; лучший завершённый план либо пустой результат |
| `turn_changed` | Ожидаемый ход не совпал или запрашивающая сторона не активна |
| `invalid_request` | Некорректный запрос |
| `not_implemented` | Зарезервировано; текущий тактический поиск не возвращает |

Приоритет: содержимое запроса → смена хода → пустая группа → поиск.
Без поиска назначения и статистика пустые. `no_plan` не является `end_turn`.
Непустой `budget_exhausted` пригоден для исполнения.

`cai_search` / `cai_support` отделяют статус ABI от причины результата:
нулевые обязательные указатели и неправильная ёмкость дают `CAI_BAD_ARGUMENT`,
неверное содержимое — `CAI_OK` с `invalid_request`. Исключения перехватываются
на границе ABI. Недостаточный буфер даёт `CAI_BUFFER_TOO_SMALL` и требуемый
размер без частичной записи. Python хранит буфер на 256 записей и расширяет
его повторным детерминированным запросом; бюджеты относятся к каждому вызову.
Числа вне int32 и неверные типы отклоняются до упаковки. ABI не проверяет
произвольные недействительные C-указатели. Python требует ABI 5.

`aggression_override=0` использует конфигурацию; 1…5 кодируют уровень + 1.
Python использует `None` либо `Aggression`. Override действует на один запрос.
`cai_support` принимает режимы `HEAL_BEFORE`, `HEAL_AFTER`, `APPROACH` (0…2).

### Конфигурация

| Параметр | По умолчанию | Допустимо |
|---|---|---|
| `position_capacity` | 6000 | 1…1 000 000 |
| `max_completed` | 2560 | 1…4000 |
| `max_branches`, `choices_per_unit` | 5, 5 | Каждый 2…9 |
| `aggression` | MEDIUM | NONE, LOW, MEDIUM, HIGH, BRAVEHEART |
| `risk_budget_base`, `risk_budget_per_kill` | 0, 1 | Каждый 0…13 |
| `privileged_cp_queries` | true | Только true; профиль без привилегий не реализован |

Значения не зажимаются молча. Время по часам не является бюджетом поиска.
Риск заменяет отсутствующие зависимости CP от опыта/личности; это число
допустимых опасных проверяемых позиций, а не прогноз количества потерь.

## Физическая модель, информация и память

`make_rules_adapter(state, observer)` фиксирует карту и наблюдателя;
`root(state, contacts)` проверяет снимок и карту. Неверные аргументы C++
сервисов, чужие ветви, ID и клетки дают `std::invalid_argument`.
`reachable` учитывает известную занятость, текущие движение и ожидание,
возвращает также исходную клетку. Для соседнего назначения используется
стоимость прямого ребра. Путь к дальней цели не предсказывает будущие контакты.
`move_intents` допускает собственный stacking для построения намерений;
реальное освобождение клетки/обмен проверяется отдельно.

`preview` и `apply` используют общую физику `combat_state` с броском 600,
без реального RNG. `forecast` возвращает предварительный нескорректированный
урон; `apply` отдельно применяет коррекции overkill и взаимной гибели.
`preview(..., true)` на частной копии обновляет движение/атаку/ожидание
атакующего, но не лечит и не начинает новый ход. Неверная команда не меняет
ветвь, возвращая код ядра; неатакующий preview даёт BAD_ACTION.
`Transition` содержит результат, принятие, прерывание контактом и новые клетки.
`actions` выдаёт команды активной стороны. `can_see` / `can_shoot` проверяют
геометрию; последний не означает наличие движения или врага в цели.
При максимальном int32 номере хода `end_turn` запрещён, переполнения нет.

Истинный снимок доступен внутреннему адаптеру; произвольное чтение скрытых
позиций для выбора цели или построения запрещено. Привилегии ограничены:

| Запрос | Разрешённые скрытые данные |
|---|---|
| `prospective_units` | Только клетки нового обзора последнего принятого перехода |
| `known_enemy` | Текущее истинное положение живого врага из активной памяти ветви |

Геометрия, местность, движение, зона контроля (ЗК), обстрел и физическое
исполнение обслуживаются ядром. Реальные команды дополнительно проверяются
организатором по `available_actions`; привилегии не расширяют их законность.

Агент обновляет реальную память через `ContactMemory.updated(observation)`.
Результат отделён от наблюдения; обратное время и чужая сторона отклоняются.
Собственный ход: `floor((int64(turn) + (active_side == observer)) / 2)`.
Видимый враг получает текущий номер; скрытый сохраняется при возрасте 0/1,
удаляется при 2. Пропуски обновлений не продлевают срок; одинаковый ход
идемпотентен. Корень и принятые переходы очищают просроченные контакты и
добавляют видимых; гипотетические переходы не меняют время последнего
реального обновления и не заменяют память агента. `reset` начинает новую память.

### Две модели угроз

| Потребитель | Модель и кэш |
|---|---|
| Тактический поиск | `CpTactics::danger`: индекс возможных атакующих от корня, кэш `(defender, tile, self_damage, killed)` в контексте одного поиска |
| Поддержка и диагностика | `DangerModel::incoming`: максимум физических одиночных атак каждого врага после достижимого перемещения, кэш `(defender, tile)` в ветви |

В тактическом индексе возможных атакующих используются полное движение,
игнорирование занятости и ЗК, исключение убитых и приближённый урон с
неизвестной исходной клеткой при необходимости подхода. Он не перестраивается
после каждого контакта. Урон защитнику учитывает накопленный самоурон.
Для известных при создании индекса врагов применяются 80% за неизвестность
цели и половина вклада при смертельном ответном ударе; видимость противнику
оценивается по исходным видимым врагам. Без тумана цель считается известной.

`DangerModel::incoming` переносит защитника на свободную проходимую клетку
(либо его текущую), снимает укрепление при переносе, оставляет всех своих и
врагов активной памяти. Остальные враги исключаются из занятости/поддержки.
Атакующим даются полное движение и новая атака без лечения. Достижимость
учитывает занятость и ЗК; берётся максимум урона из конкретных позиций с
броском 600. Поправки 80% и половины применяются к каждой атаке перед выбором
максимума. Сам запрос не меняет ветвь, обзор или память. Кэш очищается при
принятом переходе/обновлении памяти; клоны начинают с пустого кэша.

Обе модели суммируют независимые вклады врагов без ограничения HP защитника
и без согласованного ответа армии. Добавка AddFogDanger: вокруг каждого
видимого врага скрытые проходимые клетки радиуса 2 добавляют по 1 опасности
в свой радиус 2. Исчезнувшие контакты эту добавку не создают. Это не штраф
за любую скрытую клетку карты. Общего кэша между поисками нет.

## Тактический поиск

### Область, допуск и оценки

Начальная область: видимые клетки в радиусе 5 цели, радиус 2 вокруг найденных
там врагов, исходная клетка и соседи допущенных участников. Предел — 255
тактических клеток, сначала центр участника, затем соседи. Вновь видимые
клетки добавляются до того же предела. Видимые враги непосредственно за
внешней границей могут влиять на дистанции, не становясь целями атак.
Назначения движения ограничены радиусом 6 от цели; положение участника
вне этого радиуса само по себе не исключает его.

Допуск выполняется до добавления окрестностей участников. Исторический
урон прошлого хода строго больше HP означает projected-to-die: при отсутствии
врагов в исходной области юнит исключается, иначе ближний получает третью
линию. ABI не передаёт историю, используется 0; C++ контекст принимает
реальную историю явно. Дальние типы получают вторую линию, остальные — первую.
`dropSuperfluousUnits` ранжирует по лучшему предпочтительному действию,
учитывает ранения и может исключить доступного участника. Offense лидера
не передаётся, используется 0, соответствующий порогу 50 HP.
Корневой отсев не отменяет уже добавленные окрестности и маску допуска.

Оценки переносят таблицы линий и правила CP для поддерживаемой физики.
LOW/MEDIUM/HIGH/BRAVEHEART используют коэффициенты 0.7/1.1/2.3/4.2 и
пороги HP 40/20/−5/0 с исходной индексацией. NONE исключает команды атаки.
Потенциальная атака использует лучшую предварительную оценку, половину
произведения на число атак либо четверть при нуле; near-kill и kill имеют
отдельные бонусы. Конечная позиция учитывает опасность, HP, прикрытие
закончившими действия, край обзора и исходное число безопасных клеток.
Это эвристическая оценка, не доказательство оптимальности или выживания.

<a id="slot-states"></a>
### Состояния участников

| Состояние | Смысл при итоговой оценке |
|---|---|
| `Pending=0` | Ещё доступен; живой участник не проверяется как конечная позиция и не получает FINISH |
| `Finished=1` | Конечная позиция живого проверяется, учитывается в построении и получает FINISH; погибший штрафуется исходным HP |
| `Blocked=2` | Передан через CP_BLOCKED внутри поиска; пропускается итоговой оценкой, без FINISH |
| `ExcludedAtRoot=3` | Исключён до поиска: движение/ожидание, допуск или корневой отсев; без кандидатов и FINISH |

Для двух последних состояний публичная запись одинакова: CAI_BLOCKED.
Она не расходует физический ход. Пропуск Blocked с оставшимся движением
воспроизводит допущение CP о возможности дальнейшего действия/отхода;
проверка безопасного продолжения здесь отсутствует. Неизбранные свои
остаются физическими участниками, препятствиями и поддержкой.

<a id="continuation"></a>
### Продолжение движения

`MoveFlag::{None,Moved,Swapped}` независим от состояния слота. Обычный MOVE
ставит Moved; новый обычный MOVE при ненулевом флаге не предлагается.
Атака сбрасывает флаг; CP_FORCED также сбрасывает его после перемещения.
Обнаружение живого врага при MOVE сбрасывает флаг. Открытие пустых клеток
обновляет обзор/область, но само по себе не разрешает второе движение.
Продолжение всегда требует оставшегося движения и законной команды ядра;
из поддерживаемых типов только всадник сохраняет движение после атаки.

<a id="restart"></a>
### Обнаружение и RESTART

Обнаружение врага на вновь видимых клетках ставит `discovered` и создаёт
служебный RESTART после обеих частей комбинации. Запись содержит ID первого
фактического наблюдателя; клетки равны −1, движение 0. Пустой новый обзор
не создаёт RESTART. Первый контакт может прервать текущий MOVE; тот же уже
известный враг не прерывает следующий приказ. Поиск продолжает ту же ветвь
с общим бюджетом; RESTART не начинает новый поиск и не обновляет реальную
память агента. Поведение реального исполнителя описано ниже.

<a id="combo-invariants"></a>
### Комбинации и записи назначений

| Форма | Условие |
|---|---|
| `[X]` | Предпочтительное MOVE, MELEE, RANGED, FINISH_TEMP либо BLOCKED |
| `[не-MOVE, FINISH_TEMP/BLOCKED]` | Только depth-first; первый ход — атака или служебное завершение; юниты разные |
| `[SWAP, SWAP_REVERSE]` | Один физический обмен и обратная запись |
| `[CP_FORCED, MOVE]` | Блокирующий освобождает клетку основному |

Освобождение требуется конкретному
предпочтительному движению; выбирается первый подходящий выход блокировщика
с суммой оценок не меньше −10. Дальнейшая рекурсия блокировок не строится.

До физического исполнения проверяются размер 1…2, выбранные ID, виды/цели,
разные юниты пары и взаимное присутствие SWAP / SWAP_REVERSE. Обратная запись
дополнительно проверяется на соответствие фактическому свопу перед изменением
её оценки. Нарушение даёт logic_error также в release. Непринятая физическая
команда приводит к отбрасыванию временного ребёнка.

`UnitId` адресует полный ростер, `SlotIdx` — выбранную группу; неявного
преобразования между ними и в int нет. Массивы UnitValues/SlotValues принимают
свой тип индекса. Отображение выбранных ID проверяется до индексирования.

MOVE/MELEE/RANGED/SWAP физически исполняются адаптером. Назначение хранит
ID, клетки, движение, роль, оценку, урон/ответный урон, killed_unit и
command_target. MOVE.to_tile — фактическая остановка; command_target — исходный
приказ, который при контакте может быть дальше. SWAP_REVERSE описывает второго
участника одной атомарной команды. INITIAL/BLOCKED/RESTART/FINISH_TEMP служебные;
у них command_target=−1. В принятом результате FINISH_TEMP заменяется FINISH.
FINISH завершает юнита, но не ход стороны и не укрепляет его немедленно.

<a id="candidate-order"></a>
### Порядок и ранг

Предпочтительные действия оцениваются до копирования ветви; стабильное
отсечение сохраняет равные граничные оценки. Дальние атаки ограничиваются
отдельно, CP_BLOCKED с оценкой −10 добавляется после отсечения.
Сборщик рассматривает до max(5×branches, число предпочтительных / 2)
элементов общего списка; depth-first использует branches=1.
`CpCombo::score` — сумма для стабильной сортировки кандидатов.
Ранг ветви складывается отдельно по действиям, исключая CP_BLOCKED и
CP_FINISH_TEMP; поэтому сумма сортировки не обязана совпадать с приростом ранга.

Очередь предпочитает меньшие поколения, затем больший ранг и более ранний
индекс позиции. Когда минимальное поколение превышает 3, режим переключается
на большую глубину, одного принятого ребёнка и два варианта на юнит.
Порядок клеток адаптера — по индексу; стабильные сортировки сохраняют порядок
при равенстве, дополнительных критериев вида команды не вводят.
Эквивалентность учитывает свои/видимые вражеские состояния, обзор, область,
контакты, убитых и историю слотов. Вариант с не лучшим накопленным баллом
атак отсекается; устаревшая позиция при извлечении также пропускается.

<a id="early-finish"></a>
### Завершение и незавершённые участники

Терминальная позиция: все слоты не Pending либо уничтожен каждый ID
непустого исходного набора тактических врагов. Новые убийства не заменяют
исходных целей; новые враги не расширяют исходную задачу. Пустой набор
сам по себе не завершает поиск. Корень проверяется отдельно; терминальные
дети оцениваются до постановки в очередь.

При раннем завершении живые Pending, включая уже двигавшихся, остаются
доступны последующим задачам: без конечной проверки риска, вклада в
построение и FINISH. Нетронутый Pending получает +123 к итоговому баллу —
бонус CP из addFinishMovesIfAcceptable за использование меньшего числа юнитов.
Число унаследовано из CP, не выведено как оптимальное. Действовавший Pending
этого бонуса не получает. Ранее начисленные оценки действий сохраняются.

<a id="plan-acceptance"></a>
### Принятие плана

Проверяются конечные позиции Finished. Опасных допускается не больше
`risk_budget_base + risk_budget_per_kill × kills`, где kills — число убитых
врагов ветви. Бюджет не отменяет законность команд и фильтры атак.
Он не гарантирует безопасность оставшихся Pending или Blocked.

Дополнительно требуется одно из условий:

- Есть убийство либо обнаружение нового врага.
- При наличии тактических врагов улучшений построения больше ухудшений;
  при равенстве достаточно хотя бы одной MELEE/RANGED атаки в истории ветви.
- Если тактических врагов нет, суммарная дистанция до цели сократилась.

Построение и дистанции сравниваются только для проверяемых живых Finished:
первая линия стремится к дистанции 1, вторая к 2; третья уходит с дистанции 1.
Атака без убийства при преобладании ухудшений сама по себе недостаточна.
Убийство/обнаружение тоже не отменяют бюджет риска. Ожидание без улучшения
даёт no_plan. Последняя оценка позиции не начисляется дважды: для двигавшихся
добавляется max(0, конечная оценка − последняя оценка движения).
Оценка не переписывает назначения; FINISH устанавливаются только после принятия.

<a id="search-budgets"></a>
### Бюджеты и статистика

Достижение max_completed означает budget_exhausted независимо от оставшейся
очереди, в том числе при получении пригодного плана последним ребёнком.
Лимит пула также даёт budget_exhausted, когда поиск не может продолжиться.
Возвращается только уже принятый завершённый план, никогда незавершённая ветвь.

| Счётчик | Смысл |
|---|---|
| generated | Удержанные позиции, включая корень |
| checked | Обработанные неустаревшие извлечённые позиции либо терминальный корень |
| completed | Принятые завершённые позиции |
| pruned | Отклонённые кандидаты и обнаруженные дубликаты/устаревшие позиции |
| peak_positions | Пик занятых слотов; при текущем растущем пуле равен generated |

Временные отброшенные дети не входят в generated/peak_positions.

## Реальное исполнение и координатор

Организатор вызывает `act_with_planning`, если он есть, иначе обычный act.
`PlanningAgent` владеет Planner; сервис получает снимок, сторону и ход на
один вызов, `search` / `support` требуют явно переданную память. После reset
проверяется наличие Planner. Battle, RNG и сервис в обычный reset/act не
передаются. CPAgent.reset закрывает прежний контекст и очищает память/задачи.

Исполнитель выдаёт по одной штатной команде с command_target, проверяя
сторону/ход, клетки, партнёра свопа и available_actions. Служебные записи
пропускаются; SWAP_REVERSE проверяется, но не исполняется повторно. FINISH
вызывает skip, если юнит ещё доступен; для погибшего/исчерпанного/ожидающего
дополнительной команды нет. После исполнения организатор вызывает
`on_action_result(action, result, observation)` даже для последней команды.
Исключение сохраняет исполненный префикс и даёт agent_error этой фазы.

CPAgent сверяет урон, HP/смерти, клетки, движение и флаги. Новый реальный
контакт, остановка или расхождение отменяют очередь; новый поиск выполняется
при следующем выборе. Даже предсказанный контакт требует перепланирования.
Сам RESTART очередь не отменяет. Реальная память обновляется по наблюдениям.
Повтор состояния с той же задачей без прогресса завершает задачу; неверный
запрос поиска считается ошибкой интеграции, а не командой ждать.

Фазы координатора: срочное лечение → бой → лечение оставшихся → подход или
разведка → ожидание; затем end_turn. Цели выбираются по рёбрам статического
графа проходимой суши, затем ID врага/своего, с предпочтением сохраняющих смысл
назначений. Группа — до 13 ближайших доступных, равенства по ID. Радиуса 6
для исходной позиции участника нет. Если HP группы меньше HP видимых врагов
в радиусе 5 цели либо 4 от любого участника, агрессивность ограничивается
LOW; NONE сохраняется. Эта область оценки координатора отличается от
тактической области C++ поиска.
Это собственная стратегия координатора, а не перенос стратегического AI CP.

До контакта группы до четырёх исследуют никогда/давно не виденные области,
избегая уже назначенных областей. Цели удерживаются до обзора или двух
собственных ходов без сближения; заблокированные исключаются до конца
следующего собственного хода. Запомненные враги выбираются по последней
наблюдавшейся клетке, пока жив контакт; видимая пустая клетка снимает цель.
Истинные скрытые позиции не выбирают цель координатора. Кэш до 64 полей
маршрутов принадлежит агенту и не заменяет физические пути с ЗК и занятостью.

Поисков допускается два за вызов и `2N + ceil(N/13)` за ход; support-запросов
`3N + ceil(N/13)`, N фиксируется по доступным своим при начале обслуживания
хода. Пара юнит/цель не пробуется повторно без предусмотренного перепланирования.
Пустые результаты и бюджеты переводят к следующим задачам/фазам; при отсутствии
полезной задачи выдаётся skip. Эти ограничители могут приводить к ожиданию.
Известны два непокрытых требования координатора: повторный подход части
разведчиков после контакта и полезные атаки при небезопасном участнике группы;
они помечены expectedFailure, а не объявлены выполненными гарантиями.

### Поддержка

`Planner.support` возвращает тот же SearchResult и MOVE/FINISH. checked считает
оценённые достижимые клетки; остальные счётчики пула равны нулю.
До боя лечение требуется при HP < 13 либо HP < 33 без доступной атаки;
после боя: при соседнем враге danger > HP, иначе HP < 80. На безопасной
текущей клетке юнит остаётся. Оценка лечения:
`10 × (HP + healing − danger/(friends+1)) − 2 × distance`.
Healing учитывается только на текущей клетке без действий. Предпочтительны
позиции с danger < HP; иначе используется запасной выбор с сжатием опасности
после 144 и штрафами потери лечения/укрепления, обзора и соседства.

Подход рассматривает цель, первое, затем второе кольцо свободных клеток.
Выбранная клетка сокращает графовую дистанцию и имеет danger < HP; равенства
разрешаются опасностью, защитой и индексом. Один юнит получает не больше
одного MOVE за support-план, затем FINISH. Новый враг/контакт прекращает
план до FINISH. Лечение делает ядро на следующем начале своего хода;
движение HP не восстанавливает, skip сохраняет возможность лечения.

## Диагностика и оценочный стенд

`drain_diagnostics` отдаёт и очищает события задач, posture, search/support,
action/result, отмены, окончания и ожидания. Организатор добавляет сторону и
номер уже исполненной команды в необязательные replay.ai_events. Search/support
содержат назначения, причину/статистику и replanning после отмены. Скрытых
снимков и временных меток там нет; replay.steps воспроизводятся без AI.

`scenarios/combat-ai-v1.json` задаёт корпус из 148 матчей: 128 против
random/greedy, 16 CP–CP и четыре CP–CP с 26 юнитами. Каждая конфигурация
повторяется в отдельных процессах; проверяется каждый шаг реплея. `--quick`
не является полной приёмкой. `--resume` требует совпадения подписей исходников,
зависимостей, конфигурации, карт, бинарных файлов, среды и хешей артефактов.
Время решения агента измеряется отдельно от физического исполнения/сохранения;
RSS — пик всего worker до проверки реплея. Timeout технический, не игровой
исход; дерево процесса останавливается, а неподтверждённое завершение прерывает
серию. Актуальные измерения требуют нового каталога и подписанного запуска.
Старые результаты не переносятся на исправленную версию агента автоматически.

Greedy сначала атакует доступной командой видимого врага с меньшими HP,
иначе ищет одно движение с последующей атакой без оценки выгодности размена.
Проверка подхода использует только публичную карту и наблюдаемых юнитов;
после контакта продолжение выбирается заново. При отсутствии такого подхода
агент сближается или исследует. Реального PlanningState у greedy нет.

## Границы переноса и проверка соответствия

Нет городов, территориальных бонусов, гарнизонов, улучшений/pillage,
гражданских, моря/воздуха, генералов, опыта и характера лидера. Отсутствующие
входы не заменяются выдуманными эвристиками. Реальная геометрия, физический
урон и законность команд принадлежат симулятору. Предварительные оценки CP
могут отличаться от последующего физического исполнения; план проверяется
исполнением, а не объявляется оптимальным.

[Карта исходных функций](combat-ai-cp-transfer.md#соответствие-исходнику)
содержит закреплённый commit, номера строк и ограничения адаптации.
[Протокол инвариантов](combat-ai-planner-invariants.md) хранит исправления
условия раннего финиша и атрибуции контакта, версии и результаты проверок.
Они объясняют происхождение правил; актуальные определения находятся выше.

Native-группы с префиксом contract проверяют перечисленные инварианты;
модель, исполнитель, координатор и greedy имеют отдельные проверки.
Полные 49 сохранённых результатов сравниваются с библиотекой до этого аудита:
[отчёт](../artifacts/combat-ai/contract-audit-20261102.json).
Это проверка неизменности поведения, не оценка оптимальности.
