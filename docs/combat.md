# Боевое ядро CP Only

`civ5sim` — самостоятельный симулятор двух армий. Правила исполняет C++17;
Python отвечает за загрузку сценариев, команды, наблюдения и сохранения.
Запуск Civ V, GPU и библиотеки обучения не требуются.

## Сборка и запуск

Из корня проекта:

```powershell
.venv\Scripts\python.exe tools\build_combat.py
.venv\Scripts\python.exe -m civ5sim run scenarios\duel.json --commands scenarios\duel_commands.json --out build\duel-final.json --replay build\duel-replay.json
.venv\Scripts\python.exe -m civ5sim replay build\duel-replay.json
.venv\Scripts\python.exe -m unittest discover -s tests -v
.venv\Scripts\python.exe tools\benchmark_combat.py --iterations 2000
```

Сборка использует MSVC x64, установленную игру и локальный CP:
`--game "E:/civ5/Sid Meier's Civilization V"`,
`--cp E:/civ5/Community-Patch-DLL`. На Linux предусмотрена сборка `c++` в
`build/libcombat.so` с теми же исходниками игры/CP; в этой сессии проверена Windows.
Все извлечённые исходники и результаты компиляции остаются в `build/`.
Для исполнения уже собранного ядра нужны библиотека и `combat_rules.json`;
исходники игры больше не читаются.

## Организатор матча

```powershell
.venv\Scripts\python.exe -m civ5sim match scenarios\match-example.json --out build\match-example
.venv\Scripts\python.exe -m civ5sim replay build\match-example\replay.json --out build\match-example\verified.json
```

Конфигурация JSON содержит обязательные `map`, `armies`, `max_rounds` и
`agents`. `map` — объект карты либо путь относительно конфигурации;
`armies` — два непустых списка типов юнитов, необязательно одинаковых;
`max_rounds` — положительное число полных раундов. Раунд включает ход стороны
0 и ход стороны 1, а ход стороны заканчивается командой `end_turn`.
Первой всегда ходит сторона 0. После `2 * max_rounds` команд `end_turn`
фиксируется ничья независимо от потерь. Уничтожение армии проверяется после
каждой команды и немедленно приносит победу противнику. Если обе армии
уничтожены, фиксируется ничья; проверка уничтожения предшествует лимиту.

Необязательные параметры: `seed` (uint64, по умолчанию 0), `fog: true`,
`random_damage: true`, `max_calls_per_turn: 10000`. Последний ограничивает число
вызовов агента за один ход стороны; превышение — техническая ошибка, не ничья.
Каждая сторона получает свою зону `spawn_candidates` из карты. Клетки зон должны
быть уникальны, проходимы, не пересекаться и принадлежать одной связной области.
Если места недостаточно, запуск отклоняется до вызова агентов. Расстановка
случайна без повторений и воспроизводится по seed. Генерация ландшафта остаётся
отдельным шагом `civ5map generate`.

`agents` содержит две строки: встроенные `random`, `end_turn` либо
`module:factory`. Фабрика без аргументов возвращает новый экземпляр агента;
модуль должен быть доступен в Python-окружении запуска. Встроенные агенты
предназначены для проверки конвейера, не служат сильными соперниками.
Python API позволяет передавать собственные экземпляры напрямую:

```python
from civ5sim import Action, MatchConfig, RandomAgent, run_match


class MyAgent:
    def reset(self, context):
        self.side = context["side"]
        self.history = []

    def act(self, observation, actions):
        self.history.append(observation)
        return next(
            (a for a in actions if a.kind in ("melee", "ranged")),
            Action("end_turn"),
        )


config = MatchConfig(
    map="artifacts/pangaea-42/crop-01.json",
    armies=[["warrior", "archer"], ["warrior", "archer"]],
    max_rounds=100,
    seed=42,
)
match = run_match(config, [MyAgent(), RandomAgent()])
match.save("build/my-match")
```

На каждый матч нужны два независимых экземпляра. `reset(context)` вызывается
один раз перед боем; контекст содержит `map` (известный ландшафт без метаданных
и стартовых зон), `side`, известные исходные `armies`, `max_rounds`, `fog`,
`random_damage` и индивидуальный `seed`. В `act(observation, actions)`
передаются новое наблюдение `Battle.observe(side)` и кортеж допустимых `Action`.
Ответ — один из этих `Action` либо его словарное представление. Следующая
команда запрашивается у той же стороны до `end_turn`; память экземпляра
сохраняется. Входы можно сохранять и изменять, они не меняют состояние боя
или входы другого агента. Скрытые потери, полное состояние и RNG боя агентам
не передаются. Расстановка, бой и два агента используют отдельные seed,
полученные из общего seed с помощью SHA-256 по имени потока.

`run_match` возвращает `MatchOutcome` с полями `result`, `replay`, `final`;
`save(directory)` записывает `result.json`, `replay.json`, `final.json`.
Результат (`kind: civ5sim.match_result`, `schema: 1`) содержит параметры,
спецификации агентов, seed, счётчики команд/ходов/вызовов, выживших, сумму HP
и хеши исходного и финального состояния. `status` — `completed` или `error`,
`outcome` — `win`, `draw` либо `null`, `winner` — 0, 1 либо `null`.
Причина завершения находится в `reason`: `army_destroyed`,
`mutual_destruction`, `turn_limit`, `agent_error`, `invalid_action`, `action_limit`.

Исключение при создании/сбросе/вызове агента, недопустимый ответ или превышение
предела вызовов дают `status: error` без победителя. `error` содержит сторону,
фазу и сообщение. Успешно выполненная часть реплея и финальный снимок также
сохраняются; CLI возвращает код 1. Неверная конфигурация отклоняется исключением
до начала матча. Python-агенты исполняются как доверенный код в том же процессе;
принудительных таймаутов вызовов нет. Артефакты содержат полную информацию и
предназначены для анализа вне входов политики. Реплей использует существующий
формат `civ5sim.replay` и проверяется штатной командой.

## Профиль правил

Эталон — локальный **CP Only 4.22 (v144), `BALANCE_VP=0`**. Паспорт
`build/combat_rules.json` содержит commit, SHA-256 исходников CP и XML/SQL,
числовые параметры и хеши собственного ядра. Он включается в снимки;
восстановление с другим паспортом запрещено. Произвольные моды и изменения
базы не загружаются: это явно ограниченный профиль, а не эмулятор игровой БД.

| Тип в API | Ближняя сила | Дальняя сила | Очки движения | Дальность |
|---|---:|---:|---:|---:|
| `warrior` | 8 | — | 2 | — |
| `archer` | 5 | 7 | 2 | 2 |
| `chariot_archer` | 6 | 10 | 4 | 2 |
| `spearman` | 11 | — | 2 | — |
| `horseman` | 12 | — | 4 | — |

Все юниты имеют максимум 100 HP. Опыт и приобретаемые повышения отсутствуют.
Ядро ABI 2 хранит урон текущего и прошлого интервала собственного хода
(`damage_taken_this_turn`, `damage_taken_last_turn`). Суммируется урон
защитнику; ответный урон при собственной атаке исключён, как в CP.
На начале хода стороны её счётчики ротируются до лечения; лечение не
вычитается из истории. История сохраняется в clone/reset и снимках schema 2,
одинаково обновляется одиночными и пакетными командами. Реплеи используют
schema 2; прежние снимки и реплеи отклоняются. Сценарии остаются schema 1
и начинают с нулевой историей. Обычное наблюдение скрывает историю врага.

Врождённые свойства сохранены: стрелки не атакуют в ближнем бою, колесница
теряет остаток движения на пересечённой местности, конные типы не получают
положительный бонус местности и не укрепляются, всадник может двигаться после
атаки. Одна атака за ход. В CP-only у колесницы класс `ARCHER`, а новое поле
`IsMounted` остаётся ложным; бонус копейщика +50% применяется к всаднику.

Учтены ранения (`-floor(потерянные HP × 34 / 100)%` силы), местность,
укрепление, реки и фланговое преимущество. По CP фланги сравнивают поддержку
у обеих сторон; возвышенность с лесом даёт суммарно +50% защиты. Отрицательный
бонус местности действует и на конницу. Защищаясь от выстрела, стрелок
использует дальнюю силу. При избыточном смертельном уроне уменьшается ответный
урон; при потенциальной гибели обоих действует коррекция CP до одного выжившего.

Числа и порядок сверены с `CvUnit`, `CvUnitCombat`, `CvUnitMovement`,
`CvPlayer::DoUnitReset`. Укрепление — постоянные +20%, появляющиеся при начале
следующего собственного хода после бездействия. Лечение на нейтральной
территории — 10 HP в начале собственного хода, если в прошлый ход юнит
не двигался и не атаковал. Пропуск действий не мешает лечению и укреплению.
Первый переход к другой стороне также выполняет её сброс хода: сценарий
задаёт состояние непосредственно перед командами начальной стороны.

Обзор и линия обстрела используют непосредственно извлечённые при сборке
`CvPlot::changeAdjacentSight` и `CvTargeting::CanSeeDisplacementPlot` через
адаптер геометрии. Учтено дополнительное кольцо видимости высоких клеток,
которое не означает дополнительную дальность стрельбы. Таблицы обзора и
обстрела вычисляются один раз, текущая видимость обновляется счётчиками.

В случайном режиме бросок 0…1199 прибавляется к базовым 2400 перед
применением отношения сил и округлений CP. Фиксированный режим использует 600.
Используется собственный сериализуемый SplitMix64: одинаковые исходное
состояние и команды воспроизводят бой в этом симуляторе. Совпадение случайных
бросков с полной игрой по её seed не обещается.

## Сценарий и команды

Сценарий JSON имеет `schema: 1`, `kind: "civ5sim.scenario"`, `map`, `units`.
`map` — объект существующего формата карт или путь относительно файла сценария.
Параметры: `fog` и `random_damage` по умолчанию `true`, `seed` по умолчанию 0,
`active_side` по умолчанию 0. Обе стороны считаются воюющими; земля нейтральна.

Юнит: `type`, `side` (0 или 1), `tile` (индекс либо `[x,y]`), необязательные
`hp`, `moves`, `attacked`, `acted`, `fortified`, `waiting`. ID — постоянный
индекс в списке `units`, включая погибших. `moves` измеряется в **1/60 очка**:
120 для пехоты, 240 для конницы. Остальные флаги по умолчанию ложны, HP — 100.

Для начала перемещения или атаки достаточно любого положительного остатка
движения, включая 1/60 ОП. При стоимости действия выше остатка он расходуется
целиком, и юнит получает 0 ОП. Это не отменяет проходимость, дальность,
линию обстрела и ограничение числа атак за ход.

```python
from civ5sim import Action, Battle, step_batch

with Battle("scenarios/pangaea-42.json") as battle:
    observation = battle.observe()  # сведения активной стороны
    commands = battle.available_actions()
    result = battle.step(commands[0])
    if not result.ok:
        print(result.error)
    saved = battle.snapshot()       # полное состояние для сохранения/отладки
    with battle.clone() as second:
        step_batch([battle, second], [Action("end_turn"), Action("end_turn")])
```

Команды `Action(kind, unit=-1, target=-1)`:

- `move`: конечная клетка в пределах оставшегося движения. Соседняя клетка
  достигается напрямую; для дальней ищется путь с минимальными затратами
  по известным сведениям. Союзников можно проходить, но нельзя занимать их клетку.
- `melee`, `ranged`: атака указанной клетки. Для ближней атаки нужно стоять рядом.
- `swap`: обмен с союзным юнитом на соседней клетке `target`, например
  `Action("swap", unit=0, target=27)`. У обоих должны оставаться очки движения.
  Каждый оплачивает свой переход по обычным правилам местности, рек и зон
  контроля; войти можно и при остатке меньше полной стоимости перехода.
  У обоих снимается укрепление, движение запрещает лечение в следующем сбросе
  хода, использованные атаки сохраняются. Партнёр после `skip`/`fortify` с
  оставшимся движением просыпается. Обмен атомарен; дальние свопы не реализованы.
- `fortify`, `skip`: закончить действия юнита на этот ход, сохранив право
  на естественное лечение. Длительные автоматические задания не создаются.
- `end_turn`: передать ход другой стороне; `unit` и `target` не используются.

Дальний приказ движения обрабатывается по клеткам. В режиме тумана новый
контакт прерывает приказ на свободной клетке, чтобы вызывающий код мог получить
наблюдение и решить, как продолжить. Это правило интерфейса команд симулятора.
Остаток движения сохраняется. Перемещение само по себе не начинает атаку.
`result.moved` — число пройденных рёбер (у `swap` — 2 за обоих), `damage` и `retaliation` — фактически
снятые HP, силы возвращаются в сотых. Недопустимая команда возвращает
`error` и сохраняет состояние и RNG. Ошибочный формат Python-входа вызывает
`ValueError`. `preview_attack` не меняет состояние и использует фиксированный
бросок; в режиме тумана это оценка по известным сведениям.

`observe(side)` содержит маску видимости и собственных/видимых вражеских
юнитов. Враги не раскрывают внутренние флаги действий и остаток движения.
Список доступных команд и предварительный расчёт не обращаются к скрытым
позициям. Общего счётчика живых врагов в наблюдении нет. Память об исчезнувших
контактах ведёт вызывающий код через историю наблюдений.

`snapshot`, `army_status`, журналы и исходный сценарий — **полные сведения**,
их нельзя передавать принимающей решения модели в режиме тумана. Ядро
сообщает уничтожение армий, но продолжает принимать команды: лимит эпизода,
победителя и награду задаёт вызывающая программа.

## Сохранение, скорость и проверка

`snapshot()` даёт самостоятельный JSON с картой, всеми юнитами, активной
стороной, номером полухода `turn`, режимами, RNG и паспортом. `Battle(snapshot)`
восстанавливает его. `reset()` возвращает начальное состояние; переданный
сценарий/снимок должен использовать ту же карту. `clone()` копирует изменяемое
состояние и делит неизменяемые таблицы геометрии с исходным боем.

`log=True` включает журнал команд, результатов и хешей полных состояний;
`replay()` экспортирует его. CLI `replay` проверяет результаты и хеш после
каждой команды. По умолчанию журнал выключен и сериализации в боевом цикле нет.

`step_batch` выполняет по одной команде для независимых боёв за один вход в C.
Пакет последователен внутри ядра; многопоточность и обучение не добавлены.
Для сбора опыта предусмотрен `action_buffer()` — переиспользуемый массив
структур `{kind, unit, target}` int32 и его длина, без создания объектов Action
для всего списка. Буфер перезаписывается следующим вызовом.
`observation_buffer()` аналогично возвращает переиспользуемые числовые массивы
видимости и юнитов без преобразования в Python-словари. У скрытых/погибших
слотов все поля равны -1; у видимых врагов внутренние поля действий также -1.
Размер начального состава публичен. Оба буфера не следует использовать после
следующего вызова, сброса или закрытия боя. C ABI описан в
`native/combat.h`. Один экземпляр Battle нельзя одновременно менять из двух
потоков; независимые состояния разрешены. Лимиты: 4096 клеток, 128 по оси,
512 юнитов. Контекстный менеджер или `close()` освобождает память.

Проверки включают более 5000 сравнений формулы урона с отдельно скомпилированной
исходной `DoDamageMath` из CP, игровые сценарии, геометрию вырезок, режимы,
отсутствие утечек наблюдений, сохранения и пакетное исполнение. Это проверка
выделенного подмножества; полного сравнения боевых трасс с запущенной Civ V нет.

Результаты замеров сохраняются в `artifacts/combat/benchmark.json`: отдельно
команда ядра через ctypes, Python API, генерация действий, наблюдения, пакет
из 32 состояний и память. Пропускная способность `end_turn` не является
скоростью полного обучающего цикла. Память ядра оценивается по ёмкости его
контейнеров, без временных выделений, накладных расходов аллокатора и Python.

Не включены города, дороги, владение землёй, улучшения, гражданские юниты,
погрузка, ресурсы, цивилизационные/политические бонусы, повышенные уровни и XP.
Вода, горы и лёд непроходимы. Генератор карт и просмотрщик продолжают работать
в исходном формате.
