# Риск конца действий: аудит CP Only и требования к порту

Проверено 2 ноября 2026. Источник — локальный CP Only 4.22 (v144), commit
`029e5988b7726299d6446ddddaaf3782a9c46d61`. SHA-256 `CvTacticalAI.cpp`
совпадает с `combat-ai-sources.json`:
`55c9000f2504f92a8534e6bd9c9756ff4100b58286725114c57020354a6a0749`.
Ниже — статический разбор зафиксированного исходника, не замер запущенной DLL.

## Допуск исключений

`CvTacticalAI.cpp:10359–10361` вычисляет наступательность F из
`GetPersonalityAndGrandStrategy(FLAVOR_OFFENSE)` и ограничивает её диапазоном
0…10. Базовый допуск равен 1 при F > 6 и размере входного списка vUnits > 6,
иначе 0. В `addFinishMovesIfAcceptable` (`:8747`) к базе добавляется число
противников, которых ветка считает уничтоженными (`killedEnemies.size()`).

`CvGrandStrategyAI.cpp:1605`: значение объединяет индивидуальный flavor
лидера и модификатор активной глобальной стратегии. При отсутствии стратегии
берётся только индивидуальное значение. Инициализация flavor учитывает
значения лидера из XML и `RandomizeWeights` (`CvFlavorManager.cpp:424`).

Это число исключений для конечных позиций, отклонённых обычной проверкой
опасности; оно не задаёт разрешённый процент потери HP или вероятность гибели.
Проверка `CvTacticalAI.cpp:8774` дополнительно требует, чтобы опыт конкретного
юнита был строго ниже `gMedianUnitXP`. По комментарию — защита опытных юнитов.

### Обнаруженная особенность вычисления порога опыта

В этом commit `vector<int> unitXP(vUnits.size())` (`:10371`) уже создаёт N
нулевых элементов. Затем фактический опыт добавляется через `push_back`.
`nth_element` и `unitXP[unitXP.size()/2]` (`:10398–10399`) применяются ко всему
массиву вместе с начальными нулями. Для N валидных юнитов с неотрицательным
XP получается минимальный XP группы, а не её обычная медиана. Строгое условие
XP < этого значения никого из группы не пропускает. При отброшенных входных
юнитах нулей может быть ещё больше относительно добавленных значений.

Таким образом, комментарий о защите ветеранов и фактическое вычисление в
этом исходнике различаются. Проверять поведение конкретной игровой сборки
нужно отдельно; не переносить автоматически вывод на другие версии CP.

## Что делает обычную позицию неприемлемой

`ScoreCombatUnitTurnEnd` (`CvTacticalAI.cpp:7086`) учитывает HP и полученный
в ветке урон, угрозу ответа, соседних врагов и своих, прикрытие, доступность
безопасного отхода, край обзора, предыдущее убийство и агрессивность задачи.
В исходной игре есть дополнительные условия городов и цитаделей. Режим
BRAVEHEART пропускает часть проверок опасности, но не меняет саму формулу
числа исключений. Соотношение численности влияет через `getAggressionBias`.
Опыт также увеличивает численный штраф риска для ветеранов относительно
среднего опыта армии.

Отдельно F влияет на `gMinHpForTactsim = 50 - 2*F`: отбор раненых в
`dropSuperfluousUnits` может исключать или понижать приоритет юнита.
Это механизм состава группы, а не прибавка к бюджету исключений.

## Повторный поиск исходного CP

Когда завершённых позиций нет, `FindBestUnitAssignments` (`:10537`) возвращает
также проблемных юнитов через `unuseableUnits`, собранных из отказов конечной
проверки. `FindAndExecuteBestUnitAssignments` (`:10243`) может повторить поиск
без них, если остаётся непустая группа; всего обёртка делает до четырёх попыток.
Это сохраняет возможность действий остальных. Само исключение из группы
не определяет действие исключённого юнита.

## Принятый критерий обработки безвыходной позиции в порте

Пользователь уточнил: если приемлемого безопасного плана нет, но юнит может
атаковать, простое ожидание в окружении не является приемлемым ответом.
Тактический слой должен выдать полезное атакующее продолжение, включая
возможный подход, несмотря на недопустимость конечной позиции по обычной
проверке риска. Один проблемный юнит не должен блокировать полезные действия
остальных участников группы. `skip` из-за лимита вычислений не заменяет
тактическое решение. Реализация этого поведения ещё требуется.

Проверочный эпизод: `open-5-s42-f1-r0-greedy-cp`, позиция перед 051.
Колесница 7 имеет 36 HP и доступный выстрел на 31 урона по воину. Группа
`[7,9]` при базовом риске 0 возвращает `no_plan`, группа `[9]` находит план,
а разрешение одного исключения диагностически позволяет действовать обоим.
Это подтверждает причину отказа; изменение общего риска ещё не является
реализацией отдельного поведения для безвыходной позиции.
