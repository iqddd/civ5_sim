# CP imitation: советы CP на собственных траекториях сети

> Архив: исторический протокол, исследование или прежний справочник.
> Числа, команды, версии и формулировки «следующий шаг» относятся к описанному этапу.
> Проверенные статусы и ограничения: [журнал](../../experiment-ledger.md); текущее устройство: [справочник](../../rl-architecture.md).

2026-11-05. Протокол после cp-imitation-more-data. Два ограниченных цикла выполнены:
50 042 новые свободные метки, 1000 Adam steps и 512 оценочных матчей.
[Отчёт](../../../artifacts/rl/cp-imitation-own-states/report.md): основной sampling-прирост
против CP не доказан; положительный argmax-результат показан отдельно.
Дальнейшее обучение автоматически не запускалось.

## Результат, ради которого проводится опыт

Получить измеримый рост побед над CP от текущих 5/64 sample и 10/64 argmax,
обучая сеть исправлять ситуации, возникающие после её собственных решений.
Текущий baseline — best epoch 10 more-data, Adam step 1580,
SHA256 d59fe6aab33174ec1ac246fafacabbf4db1ca61c96f5078c737d66c34561e6cc.

Это один ограниченный опыт из двух циклов «собрать → обучить», с полными
боями. Никаких предварительных кампаний на микрозадачах. Цель проекта
75% побед над CP сохраняется; имитация готовит политику, а не гарантирует
превосходство над учителем. После этого опыта не продолжать BC автоматически
ради очередного улучшения CE.

## Сбор: 2 × 25 000 новых свободных меток

- Сеть выполняет все команды. CP на её стороне только рекомендует одну
  легальную команду в текущем состоянии; рекомендация становится CE-меткой.
  Учитель не перехватывает управление. Forced-команды сохраняются для
  истории, но не считаются свободными метками и не входят в CE.
- Два цикла по 25 000 новых меток, завершать начатые эпизоды/волну.
  Первый собирается текущим baseline; второй — выбранной моделью первого
  цикла. Все метки первого цикла доступны при обучении второго.
- Матчи по равномерному расписанию: CP/greedy = 1:1 и
  sample T=1/argmax поведения сети = 1:1. Перекрёстно сбалансировать стороны
  и контактные/разделённые старты; показать фактические доли меток, поскольку
  длина эпизодов различается. Не фильтровать поражения или совпадения с CP.
- Те же 57 training-worlds, 228 crops, 10×10, воин+лучник по 100 HP,
  30 раундов, fog/random damage и CP SearchConfig. Новые расстановки и
  streams; namespace нового опыта, seed 17. Без изменения лимита раундов.
- CPU 4 workers; максимум 30 минут сбора на цикл. Сохранить точные времена
  policy inference и CP advice. Если объём не помещается, зафиксировать
  недобор; автоматически не продлевать бюджет и не менять SearchConfig.

## Самое важное в реализации

У каждой строки раздельно хранить публичное observation, упорядоченный
legal list, teacher_action и executed_action. Оба индекса проверять по
этому списку. CE получает teacher_action. Previous-action, наблюдаемая
история и GRU-префиксы строятся по executed_action и фактическим observation.
Forced states тоже проходят через память. Префиксы пересчитываются текущими
весами без градиента, как сейчас; GRU сбрасывается только между эпизодами.

Учитель-советчик требует небольшого отдельного адаптера:

- Публичная память контактов/исследования развивается по фактической
  траектории с самого начала матча, включая результат исполненной команды.
- На каждом запросе CP заново планирует из фактического состояния. Очередь,
  pending assignment и прочие обязательства неисполненной рекомендации
  не переносятся на следующий запрос. Не подставлять результат команды
  сети как успешное исполнение иной команды CP.
- Это явно режим CP-советчика с перепланированием, а не утверждение о
  побитовой эквивалентности обычному CP с продолжаемым планом. Обычный
  CP-противник остаётся прежним. Политика сброса тактического состояния
  должна быть записана в конфиге/отчёте и проверена на коротких траекториях.
- Planning services живут только внутри запроса; состояние и RNG настоящего
  боя не меняются при запросе совета. Советчик и CP-противник независимы.
  Сеть не получает planning services, скрытые позиции, оценки планов или
  внутреннюю память CP. Привилегии учителя остаются прежними.

Для этого этапа достаточно обёртки обычного match runner. Перенос CP в
PPO-collector, обучение планам и перестройка симулятора не нужны.

## Обучение: до 1000 новых Adam steps

- Начать с model + Adam текущего best, новая lineage и shuffle seed 17.
  Архитектура C/GRU и numerics прежние, value head frozen.
- LR 1e−4, Adam betas (0,9; 0,999), eps 1e−5, weight decay 0,
  gradient clipping 0,5. Только CE, без entropy/value loss и LR schedule.
- Каждый цикл максимум 500 Adam steps. На шаг 1024 реальные свободные
  метки: 512 из исходного корпуса 100 040 и 512 из накопленных новых.
  CE — среднее по 1024 меткам. Выборка с повторением между проходами;
  равный вес меток внутри каждого источника. Сохранить последовательности
  и полные фактические префиксы, не перемешивать время внутри фрагментов.
- Microbatch 8 последовательностей, fragment 128, spatial block 32;
  размеры не менять ради загрузки GPU. За цикл получается 512 000
  предъявлений меток, а не 512 000 новых игровых решений.
- Максимум 20 минут optimizer work суммарно, без автоматического продления.
  Никакой ранней остановки по одной неудачной боевой оценке.

## Выбор модели и оценка

До первого обновления собрать и заморозить небольшой дополнительный dev:
около 2000 свободных советов CP на траекториях baseline, на новых
расстановках семи holdout-worlds, с тем же балансом соперников/режимов.
Эти эпизоды никогда не поступают в обучение. Старые 2485 holdout-меток
сохраняются. Новый dev неизменен в обоих циклах, даже когда сеть меняется.

Каждые 100 Adam steps измерять обе CE и accuracy по типам, а также
type/unit/cell для move. Выбирать модель по заранее фиксированному
0,5 × old-holdout CE + 0,5 × own-state-dev CE; tie — более ранняя.
Исходная модель входит в кандидаты. Между циклами восстанавливать model
и Adam выбранного checkpoint, учитывать все фактически выполненные шаги
в бюджете, включая отброшенные при выборе более ранней модели.

В конце каждого цикла оценить выбранный checkpoint: прежние 64 матча CP
и 64 greedy в sample T=1, отдельно столько же argmax. Максимум 512 новых
оценочных матчей; повторный checkpoint переиспользует свою оценку.
Матчи не участвуют в выборе checkpoint. Основной результат остаётся
sample; argmax показывается отдельно, как в родительском опыте.

Основной критерий полезности — прирост побед над CP против more-data
baseline и положительная нижняя граница парного 95% bootstrap-интервала
по parent-worlds для итогового sample. Если интервал пересекает ноль,
результат неопределённый, даже если точечный win rate вырос. Argmax,
greedy, ничьи и срезы показывать как дополнительные результаты, без
подмены основной метрики. 75% не объявлять критерием прохождения этого
промежуточного опыта и не обещать заранее.

Validation уже используется для разработки; test остаётся закрытым.
Новые training seeds и подтверждающий test не добавлять в этот этап.

## Ограниченная проверка и дальнейшее решение

Перед сбором нужны несколько коротких проверок тихих ошибок: разные
teacher/executed команды не подменяют историю; запрос совета не меняет
battle/RNG; память не переходит между эпизодами; скрытые данные не входят
в признаки сети. Это основания для точечных тестов по AGENTS.md. Полный
suite и новое тестовое окружение не нужны.

Скорость измерять по первым рабочим волнам, их данные включать в корпус.
Для этого опыта пользователь явно снял требование GPU Core Load ≥80%.
NVML-телеметрию сохранять информационно, без нового порога и без отдельной
кампании оптимизации. Общая политика AGENTS.md для других опытов сохраняется.

Для сбора действует устойчивый ETA-stop: после ≥64 матчей и ≥60 секунд
сравнивать общий темп с последними 32 матчами. При отношении большего темпа
к меньшему ≤1,25 прогноз считается устойчивым. Если даже больший темп
три завершённые волны подряд предсказывает окончание позже 1800 секунд,
сбор остановить. Достигнутая квота приоритетнее ETA; иначе действует
обычный предел 30 минут. Недобор прекращает дальнейшие фазы опыта.

Own-state dev: ≥2000 свободных меток, отдельный предел 30 минут, до обучения.
После начала обучения всё время внутри update, включая динамические
захваты графов, входит в общий бюджет 1200 секунд. Подготовка, первоначальный
прогрев без Adam.step и offline evaluation учитываются отдельно.
При временной остановке дополнительно измерять последний завершённый шаг.
Между циклами откатываются только model/Adam; фактические расходы и RNG
выборки продолжаются. При расширении new-pool начинается новый равномерный
проход по обоим циклам с продолжаемым RNG.

Если растут победы над CP — есть основание масштабировать этот способ
сбора. Если улучшается только CE, следующая цель — оптимизация результата
боя через RL от лучшей полученной политики, с отдельно ограниченным
PPO-опытом. Не назначать третье расширение BC по умолчанию. Этот опыт
проверяет практическую комбинацию собственных траекторий и обучения
против CP; отдельные причинные вклады двух изменений не изолируются.
