# Следующий шаг: первый опыт имитации CP в полном бою

Рабочее направление, 2026-11-04. Один ограниченный опыт; ещё не реализован и не запущен. Заменяет прежний слишком широкий план в этом файле.

## Какой вопрос решаем

**Может ли существующая сеть, обученная на конкретных командах CP, самостоятельно выигрывать полные бои двух небольших армий?**

В D1 чистое PPO не получило побед за 4096 тренировочных эпизодов. Теперь проверяем способ получить стартовый боевой навык из примеров законченного боя: движение, атаки и завершение ходов вместе. Конечная цель остаётся 75% побед над CP на целевом benchmark. Этот опыт не обещает достичь её; он должен дать пригодную отправную точку для дальнейшего улучшения либо показать конкретную проблему имитации.

## Что сделать

Три результата: небольшой корпус команд CP, обученный имитацией checkpoint модели C, сравнение исходной и обученной сети против CP и greedy.

**Без PPO, self-play, новой архитектуры, изменения reward, отдельной проверки движения и интеграции CP в RL Collector/DecisionEnv.** Использовать существующий `civ5sim.match.run_match`: он уже обслуживает CP planning service и `on_action_result`; сеть подключается как обычный RLAgent. Добавить сохранение учебных пар и supervised loop. Планы CP не являются учебными метками — только выбранная команда.

## Бои и данные

| Параметр | Значение |
|---|---|
| Карта | 10×10, обычный рельеф из существующих train-worlds |
| Армии | Воин + лучник с каждой стороны, все по 100 HP |
| Правила | Туман, случайный урон, обычные лечение и действия |
| Горизонт | До 30 раундов |
| Старты | Половина контактные, половина разделённые |
| Демонстрационные матчи | CP против greedy; сторона CP чередуется |
| Целевой объём | 20 000 training-решений CP с ≥2 легальными действиями |

Использовать существующие средства подготовки карт и расстановок. Зафиксировать cases/seeds; не отбирать позиции по исходам. Сохранять все завершённые CP-траектории, включая поражения и ничьи. Последний начатый матч завершать, превышение объёма учитывать.

Данные: публичное наблюдение, полный legal list, выбранная CP-команда, границы эпизода и outcome. Вынужденные команды сохранять для истории, но исключить из CE loss, точности и целевых 20 тысяч меток. Не оставлять только атаки или победные эпизоды.

Заранее отвести 10% train-worlds целиком под offline holdout; его метки не входят в training-объём. Основные validation и test не используются как demonstrations. Учитель работает с текущим SearchConfig, записанным в паспорт. Его привилегии не передаются сети: никаких скрытых координат, CP scores и планов во входах. Метка может зависеть от недоступных сети сведений; 100% совпадения с учителем не требуется.

## Обучение

| Параметр | Значение |
|---|---|
| Модель | Прежняя C с GRU и прежними входами |
| Инициализация | Свежая сеть seed 17, сохранить initial |
| Loss | Cross-entropy CP-команды среди легальных действий |
| Adam | LR=1e−4; betas=(0,9; 0,999), eps=1e−5, weight_decay=0 |
| Бюджет | 3 эпохи по training demonstrations |
| Minibatch | 1024 решения с ≥2 альтернативами; остаток нормировать по фактическому числу |
| Фрагменты | До 128 последовательных решений; microbatch до 8 фрагментов |
| GRU | Prefix текущими весами без градиента; сброс между эпизодами |
| Clipping | Global gradient norm 0,5 |
| Numerics | Прежние BF16 spatial и FP32 GRU/головы/loss |

Вынужденные действия проходят через историю с нулевым весом CE. Не склеивать состояния разных эпизодов. Value loss и entropy bonus выключены, value head не обучать. Не выдавать демонстрации за on-policy PPO rollout. Сохранить checkpoint каждой эпохи; результат — последняя завершённая эпоха, без выбора лучшей по просмотру боёв.

## Оценка

Заранее зафиксировать **32 validation-расстановки × обе стороны = 64 матча на соперника**, в том же формате 10×10, 2×2, 30 раундов. Initial и финальная BC-сеть играют против CP и greedy: всего 256 матчей. Дополнительно CP против greedy на тех же случаях — 64 матча для характеристики учителя. Policy sample, temperature=1, matched seeds; неизменные настройки CP.

Публиковать W/D/L и изменение win rate. Ничьи не считать победами. На teacher holdout — CE и точность по типам команд без вынужденных действий. В боях — движение, атаки, ничьи по лимиту и несколько полных реплеев. Точность команд не заменяет результат боя.

**Желаемый результат — победы в полных боях и заметный рост относительно initial, прежде всего против CP.** Это малый dev benchmark метода, а не подтверждение конечных 75% на обычных картах 16×16. Не назначать искусственный процент, автоматически открывающий следующую стадию: выборка небольшая, оцениваем полезность метода.

- BC дала боеспособную policy: следующий отдельный опыт — проверить улучшение этой policy через PPO. Его настройки определяются после результата.
- Команды копируются, но бои проигрываются: разобрать первые существенные расхождения собственных траекторий с примерами учителя. Не возвращаться автоматически к лестнице микрозадач.
- CE не снижается: проверить данные, индексы команд и обучение, прежде чем менять архитектуру.

## Стоимость и проверки

Сначала **8 полных CP–greedy матчей** для замера стоимости генерации и отдельный замер latency RLAgent. Эти матчи можно включить в demonstrations, если они принадлежат train. Оценить время 20 тысяч меток и 320 оценочных матчей. Во время supervised epochs CP не вызывается.

Предлагаемый предел сбора — 1 час, обучения — 30 минут; закончить начатый матч/minibatch. Если целевой корпус не помещается в бюджет, сохранить фактический объём и состав, затем решить по измерениям, нужен ли меньший пилот или оптимизация генерации. Не запускать автоматически обучение на произвольной малой выборке. Стоимость evaluation оценить отдельно до длинного запуска. Это пределы предлагаемого опыта, а не замеры времени.

Проверять главное: соответствие команды CP публичному legal list, отсутствие закрытых данных во входах сети, разделение по мирам, границы памяти и CE normalization. Повторно исполнить несколько сохранённых боёв. Не расширять задачу в тестовую инфраструктуру.

Итог — один отчёт «данные → обучение → сила в бою», checkpoint и фактические затраты. Закрытый test, seed 42 и последующее PPO в этот шаг не входят.
